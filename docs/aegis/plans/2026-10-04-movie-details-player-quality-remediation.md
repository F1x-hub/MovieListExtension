## Goal

Привести страницу деталей и плеер к предсказуемому качеству: устранить
подтверждённые баги, закрыть небезопасные места, привести UI к дизайн-системе и
разрезать `movie-details.js` так, чтобы подобные баги перестали появляться.

Критерий успеха: каждый баг из аудита закрыт регрессионным тестом, который до
исправления падает; ручная проверка фильма и сериала на KinoGo/Ex-FS/Seasonvar
проходит в тёмной и светлой теме.

## Исходные факты (аудит 2026-10-04)

- `movie-details.js` — 13 925 строк, ~1 180 методов, 112 `addEventListener` /
  9 `removeEventListener`, 161 `console.*`, 85 `innerHTML`.
- Все существующие контракт-тесты плеера и деталей зелёные, но ни один из
  найденных багов не ловят. Поэтому каждая фаза начинается с теста.
- Проверка `isSeries` продублирована трижды: `movie-details.js:2173`, `:4352`,
  `:4566`.

## Принципы

1. Сначала падающий тест, потом исправление.
2. Одна фаза — один логический PR; фазы 1–2 можно делать параллельно, фаза 6
   только после 1–2.
3. Без изменения поведения вне описанного; рефакторинг фазы 6 — строго с
   паритетом поведения.
4. Новые скрипты подключаются как в остальном проекте (classic scripts в HTML),
   с учётом `tests/htmlScriptModuleContract.test.js` и `npm run build`.

## Фаза 1. Критические баги (P0, ≈1.5 дня)

### 1.1 Промпт автоперехода удаляется из DOM

Причина: `#playerAutoNextPrompt` и стартовый лоадер лежат внутри
`#videoContainer`, который очищается `innerHTML = ''` минимум в 8 местах.

Исправление:
- В `movie-details.html` обернуть `#videoContainer` в `.player-stage`
  (`position: relative`) и вынести промпт в сиблинг-слой
  `.player-stage__overlay`. В `player.css` позиционирование промпта перенести
  на `.player-stage`.
- Ввести единственного владельца содержимого поверхности:
  `PlayerSurface.clear()`, `PlayerSurface.showPlaceholder(state, text)`,
  `PlayerSurface.mountIframe(url, opts)`. Заменить все прямые записи в
  `videoContainer.innerHTML` (8544, 8795, 8901, 8987, 11088, 11406, 11456,
  11546, 11580, 11834) на эти методы.
- Лоадер создаётся `showPlaceholder('loading')`, а не живёт в статической
  разметке.

### 1.2 Стрелки серий у фильма

Причина: `movie-details.js:6616` включает canonical picker для `exfs`/`kinogo`
без проверки, что это сериал; `player-cleaner.js:3145` в этом режиме
принудительно показывает стрелки.

Исправление:
- Один хелпер `isSeriesContent(movie, episodes)` вместо трёх копий: истина, если
  тип сериальный **или** есть непустой список сезонов/серий (это покрывает
  аниме-сериалы и не ломает аниме-фильмы).
- Отправлять `SET_CANONICAL_PICKER_MODE` с `enabled: isSeriesContent(...)`
  и новым полем `hasEpisodes`.
- В `player-cleaner.js` показывать стрелки только при
  `enabled && hasEpisodes`; при `enabled: false` — скрывать, а не оставлять
  предыдущее состояние.
- Скрывать `#playerNavControls` в шапке модала для фильмов (сейчас проверить
  и закрепить тестом).

### 1.3 «Закрыть» не закрывает

Сейчас крестик и Esc вызывают `minimizePlayer()`; для iframe пауза
«вслепую» через 800 мс — звук может продолжаться.

Исправление (решение по умолчанию, см. «Открытые вопросы»):
- Крестик и Esc — **закрыть**: сохранить прогресс, `destroyPlayer()`, вернуть
  фокус на кнопку «Смотреть».
- Отдельная кнопка «Свернуть» в шапке — текущее поведение minimize.
- Если при сворачивании iframe не подтвердил паузу, выгрузить iframe в скрытый
  registry-контейнер (как делает `unmountActivePlayer`) вместо надежды на
  `PAUSE`; при восстановлении — повторный mount с resume.
- Обновить `title`/`aria-label` («Закрыть плеер (Esc)», «Свернуть плеер»).

### 1.4 Кнопка «Аннонсировать»

`movie-details.js:2018`: исправить на «Анонсировать», вынести в
`locales.js` (`movie_details.announce`), заменить эмодзи 📣 на монохромную SVG
из общего набора иконок.

Проверка фазы: `npm run lint`, тест фазы 0, `npm run test:media-player`,
`node tests/playerLifecycle.test.js`, `node tests/playerEpisodeRestoreRace.test.js`,
`npm test`, `npm run build`. Ручные сценарии: фильм на KinoGo (нет стрелок),
сериал на Ex-FS (стрелки работают, автопереход появляется после смены

## Фаза 2. Безопасность сообщений и разметки (P1, ≈1.5 дня)

### 2.1 Вставка URL/текста в разметку
- `PlayerSurface.mountIframe()` строит iframe через `createElement`,
  `iframe.src = url` только после `isAllowedPlayerUrl(url)`: протокол `https:`
  (или `chrome-extension:` своего id), хост из allowlist провайдеров/
  `host_permissions`.
- Плейсхолдеры — только `textContent`; постер — `style.backgroundImage` после
  проверки URL.
- Пройти оставшиеся `innerHTML` в `movie-details.js`: каждое `${…}` с внешними
  данными — через `escapeHtml` либо перевод на DOM API. Добавить статический
  контракт-тест на модуль плеера: шаблоны `innerHTML` без `escapeHtml` для
  интерполяций запрещены.

### 2.2 Входящие сообщения в `player-cleaner.js`
- Объединить три `message`-слушателя (354, 1167, 5277) в один диспетчер.
- Хост-команды (`RESET_PERMANENT_VIDEO`, `SET_CANONICAL_PICKER_MODE`, `PAUSE`,
  `RESTORE_PROGRESS`, `ANIME_SKIP_DATA`) принимать только при
  `event.source === window.parent` и
  `event.origin === 'chrome-extension://' + chrome.runtime.id`.

### 2.3 Исходящие сообщения
- Host→iframe: хелпер `postToPlayerFrame(iframe, msg)` с
  `targetOrigin = new URL(iframe.src).origin`.
- Iframe→host: `postToHost(msg)` с origin расширения (уже есть заготовка у
  `player-cleaner.js:283`). `CLOSE_EXTENSION_PLAYER` в embedded-режиме — на
  origin родителя из `location.ancestorOrigins`/известного хоста.
- Убрать `'*'` из `sendAnimeSkipTimes`, `tryPauseVideo`, canonical picker,
  прогресса, PiP, `PLAYER_READY`.

Реализация (2026-10-04), отличия от исходного плана:
- allowlist хостов не введён: у провайдеров много зеркал, поэтому проверяется
  схема (`https:`/`http:`/`chrome-extension:`), а адрес нормализуется и
  экранируется для атрибута;
- `window.postMessage(…, '*')` самой страницы себе (Seasonvar, anime skip,
  `RESET_PERMANENT_VIDEO`) оставлен: сообщение не покидает окно;
- оставшиеся `innerHTML` вне кода плеера не пересматривались.

Проверка: тесты фазы 0, `node tests/playerCleanerIsolation.test.js`,
`node tests/providerAdIsolation.test.js`, `npm run test-player-cleaner-selection`,
`npm test`, `npm run build`; ручной прогон всех пяти провайдеров (сообщения
доходят, ничего не сломалось в embedded-режиме на сайте провайдера).

## Фаза 5. UX страницы деталей (P2, ≈2 дня)

- **Дубль названия:** при наличии title-logo логотип становится визуальным
  `h1` (текст названия — `visually-hidden`), текстовый заголовок справа не
  выводится; остаётся eyebrow «Фильм» и оригинальное название.
- **Пустые поля:** общий `renderMetaRow(label, value)` возвращает `''` для
  пустого значения — убирает «Слоган: —» и аналоги.
- **Страны:** локализовать по ISO-коду (`production_countries[].iso_3166_1`)
  через `Intl.DisplayNames(locale, { type: 'region' })`; словарь из
  `random.countries` — только запасной путь.
- **Подписи:** единый формат без двоеточий в `locales.js`
  (`movie_details.meta.*`).
- **Логотипы студий:** нейтральная светлая подложка для логотипа в тёмной теме
  (контентный цвет остаётся внутри логотипа, как разрешает дизайн-система);
  если логотип не загрузился — только текст.
- **Числа:** `formatVotes` → `Intl.NumberFormat(locale, { notation: 'compact' })`
  («2,2 тыс.»); деньги → `Intl.NumberFormat(locale, { style: 'currency',
  currency, maximumFractionDigits: 0 })`; моноширинный шрифт в блоке рейтингов
  заменить на `font-variant-numeric: tabular-nums`.
- **Рейтинги:** TMDB перенести в блок рейтингов третьей плиткой рядом с
  Кинопоиском и IMDb.
- **Иерархия кнопок:** «Смотреть» — primary, «Оценить» — secondary,
  «Анонсировать» — tertiary или пункт меню `⋮` (см. «Открытые вопросы»).
- **Цвета:** 394 литерала в `movie-details.css` — заменить chromatic-литералы
  (`#10b981`, `#f59e0b`, `#fbbf24`, `#ef4444` …) на semantic `--ui-*` роли;
  inline `style="color: #ef4444"` в `movie-details.html:48` → класс с danger-
  ролью. Статус «Выпущен» оставить семантическим, но с иконкой.

Реализация (2026-10-04), отличия от исходного плана:
- страны: TMDB отдаёт только английские названия без ISO-кода, поэтому код
  восстанавливается обратным поиском по `Intl.DisplayNames('en')` с таблицей
  алиасов; формат данных и кэш не менялись;
- двоеточия убираются при выводе (`metaLabel`), а не в `locales.js`: эти
  строки также использует страница поиска;
- логотипы студий: сплошная светлая подложка вместо половинчатой — чисто
  белые логотипы на ней теряются (компромисс в пользу типичных TMDB-марок);
- моноширинный `--font-data` оставлен у крупных значений рейтинга, заменён
  только у мелких подписей голосов и сумм;
- не сделано: перенос TMDB в блок рейтингов к Кинопоиску/IMDb и иконка у
  статуса «Выпущен» (у бейджа уже есть текстовая подпись).

## Фаза 6. Архитектура (P3, итеративно, ≈1–2 недели)

Strangler-подход: по одному модулю на PR, каждый с паритетными тестами.
Порядок по выгоде:

1. **`ModalStack`** — единый обработчик Esc/Tab вместо цепочки `if`
   (`movie-details.js:671`, `:5139`); состояние через `hidden`/`data-open`,
   а не `style.display`.
2. **`PlayerSurface`** (начат в фазе 1) — единственный владелец DOM поверхности.
3. **`PlayerModalController`** — open/close/minimize/restore/focus, связь с
   `PlaybackController`.
4. **`TorrentSourcePanel`** (~1 500 строк 9242–10850).
5. **`WatchRoomPanel`**.
6. **`MovieDetailsMetaRenderer`** — таблица метаданных, рейтинги, студии.

Прогресс (2026-10-04):
- 6.1 `ModalStack` сделан: `src/pages/movie-details/ModalStack.js`, слои с
  явным `order`, единственный `keydown` на странице; поведение Esc/Tab
  сохранено, контракт-тесты переписаны с текста цепочки `if` на порядок слоёв.
- 6.2 `PlayerSurface` сделан: `src/pages/movie-details/PlayerSurface.js` —
  единственный писатель `#videoContainer` из MovieDetails (clear,
  showPlaceholder, mountFrame, mountElement, showPoster, getActiveFrame);
  проверка URL и экранирование перенесены туда. Чтения контейнера
  (`querySelector('video'|'iframe')`) пока остались в MovieDetails; парсеры
  по-прежнему рендерят в контейнер через `renderPlayer()`. Харнессы
  `playerSwitchTransactions` и `movieDetailsRendering` подгружают модуль в vm.
- 6.3 `PlayerModalController` сделан: видимое состояние окна плеера
  (открыто / свёрнуто / PiP / скрыто, док восстановления, блокировка
  прокрутки, фокус) вынесено в `PlayerModalController.js`.
- 6.4 `TorrentSourcePanel` сделан как шаг strangler: ~1 600 строк методов
  перенесены без изменений в `TorrentSourcePanel.js` и устанавливаются в
  прототип `MovieDetailsManager` (установщик падает при конфликте имён).
  Состояние пока общее через `this`; превращение в компонент со своим
  состоянием — следующий шаг. `movie-details.js`: 14 243 → 12 586 строк.
- 6.5 `WatchRoomPanel` и 6.6 `MetaRenderer` сделаны тем же установщиком
  (перенос без изменений). `movie-details.js`: 11 935 строк.
- Цель < 6 000 строк не достигнута. Оставшийся объём — в основном
  `createDetailedMovieCard` и связанные шаблоны, рекомендации/франшизы,
  сезоны, рецензии и комментарии, загрузка источников (`loadParserSource`,
  `changeVideoSource`, реестр плееров). Следующий проход: вынести загрузку
  источников и реестр плееров в отдельный модуль, затем секции страницы
  (сезоны, рецензии/комментарии, рекомендации/франшизы) по одной.
- Долг установщика: три одинаковых функции `install*` в панелях; при
  следующем проходе превратить панели в компоненты со своим состоянием и
  убрать установщики.
- Наблюдение: многие тесты собирают методы из исходника `movie-details.js` по
  имени (`compileMethod`, `extractMethod`), поэтому каждый следующий вынос
  модуля требует переписать эти тесты на импорт нового модуля.
- После фаз 1–5 файл вырос до ~14 270 строк; цель < 6 000 остаётся.

Сквозные правила для новых модулей:
- подписки через `AbortController` на mount; `destroy()` отменяет все
  слушатели, таймеры и `postMessage`-ожидания;
- логирование через `debugLog(scope, …)` под флагом; убрать трассировки
  `[SkipError]`, `[ExFsBridgeTrace]`, `[WatchRoomUITrace]` и закомментированные
  логи (сверить с `tests/runtimeDebugCleanup.test.js`).

Цель: `movie-details.js` < 6 000 строк после пунктов 1–5.
