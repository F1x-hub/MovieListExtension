# Kinopoisk API через Firebase Secret Manager

## Цель

Убрать ключи Kinopoisk API из расширения и сборки, направив запросы через
аутентифицированную Firebase Cloud Function, которая получает ключи из Secret
Manager и выполняет ограниченную ротацию/повторы.

## Одобренное решение

- Cloud Function `kinopoiskProxy` проверяет Firebase ID token.
- Прокси принимает только GET/OPTIONS и только разрешённые пути Kinopoisk API.
- Секрет хранится как `KINOPOISK_API_KEYS`; поддерживается JSON-массив ключей.
- Ротация выполняется на сервере при 401/402/403; повторы для 429, 5xx и
  сетевых таймаутов ограничены.
- Клиент и service worker не содержат API-ключей и не делают прямых запросов к
  API Kinopoisk.
- Ошибки наружу нормализуются в `AUTH_REQUIRED`, `KP_QUOTA_EXHAUSTED` и
  `KP_UPSTREAM_UNAVAILABLE` без раскрытия секретов.
- Существующие запросы к сайту Kinopoisk для скрейпинга не изменяются.

## Безопасность и эксплуатация

- Не выполнять `firebase deploy`, установку секретов или отзыв старых ключей
  без отдельного подтверждения пользователя.
- Документировать порядок запуска: сначала секрет и прокси, затем расширение,
  затем отзыв ранее раскрытых ключей.
- Не логировать Authorization, значения секретов и URL с секретными данными.
- Ошибка отсутствующего секрета должна быть диагностируемой оператору, но не
  раскрывать конфигурацию клиенту.

## Проверка готовности

- `npm run lint`
- `npm test`
- `npm run build`
- целевые тесты прокси/транспорта
- `git diff --check`
- поиск прежних ключей и прямых Kinopoisk API URL в `src`, `functions` и `dist`

## Отдельный операционный этап

После проверки сборки пользователь вручную задаёт `KINOPOISK_API_KEYS` в
Firebase Secret Manager, деплоит функцию, устанавливает расширение и только
после подтверждения работоспособности отзывает старые ключи.
