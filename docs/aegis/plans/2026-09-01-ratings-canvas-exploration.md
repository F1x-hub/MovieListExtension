# План: Canvas-режим для изучения оценённых фильмов

**Дата:** 2026-09-01  
**Статус:** superseded; Focus mode retired by `2026-09-02-retire-ratings-focus-mode.md`  
**Область:** страница оценённых фильмов, режим «Сетка/Сфера», Canvas 2D

## 1. Цель и зафиксированное поведение

Сделать на странице оценок альтернативный режим просмотра коллекции:

- все фильмы находятся в плотной детерминированной сетке;
- в обычном состоянии постеры маленькие и выглядят как точки/неразборчивые
  карточки;
- движение курсора создаёт локальную линзу только вокруг текущего места;
- ближайшие постеры плавно увеличиваются в своих ячейках, а после ухода курсора
  плавно возвращаются к исходному размеру;
- наведение показывает фильм в панели предпросмотра;
- клик фиксирует фильм и открывает его информацию;
- фильтры и сортировка меняют набор фильмов, но не ломают соответствие постера и
  данных фильма;
- обычная карточная сетка остаётся доступной и используется по умолчанию.

Приоритет имеет последняя формулировка пользователя. Скриншоты и видео являются
референсом поведения, а не инструкциями копировать весь внутренний движок сайта.
В первой версии не требуется воспроизводить настоящую сферу, WebGL-физику,
Voronoi-вычисления или отображение десятков тысяч постеров.

## 3. Архитектурное решение

### Выбранный путь

Использовать один Canvas 2D с фиксированной сеткой и локальной функцией
увеличения. Для примерно 255 фильмов это проще отлаживать и достаточно быстро.
Координаты постеров вычисляются один раз для текущего набора, а движение курсора
меняет только производное состояние масштаба/прозрачности.

### Что сознательно не копируем в первой версии

- DOM-сетку из сотен независимых карточек;
- стартовые координаты `(0, 0)` с последующей «доставкой» постеров в ячейки;
- псевдосферу через случайные `translate/rotate`;
- WebGL-текстурные атласы, DDS/KTX и force simulation;
- сортировку массива фильмов ради визуального z-order;
- загрузку JSON как будто это изображения.

### Почему это решение безопаснее

Главная проблема из референсных попыток — потеря связи между визуальной ячейкой
и объектом фильма. Поэтому источник истины должен быть один: стабильный ID фильма
и его стабильный индекс в текущем snapshot фильтра. Canvas только рисует этот
snapshot и не меняет его порядок.

## 4. Обязательные контракты и инварианты

1. **Идентичность.** Каждый элемент имеет `movieId`, ссылку/нормализованное DTO и
   `layoutIndex`. После фильтрации создаётся новый snapshot; старые screen bounds
   и hit-test данные не переиспользуются для другого фильма.
2. **Позиция.** Для каждого элемента сначала вычисляются реальные `baseX/baseY`
   сетки. Новая запись немедленно инициализируется в своей ячейке — никогда не
   `(0, 0)`. До загрузки изображения на месте остаётся placeholder.
3. **Сетка.** `baseX/baseY` исходной сетки не меняются от движения курсора.
   Экранные `x/y` вычисляются для всех ячеек через общую монотонную radial
   transform; размер и визуальный приоритет остаются отдельными производными.
4. **Координаты.** Pointer coordinates переводятся из `clientX/clientY` через
   `getBoundingClientRect()` в CSS-пиксели Canvas. Размер backing store учитывает
   `devicePixelRatio`, но hit-test работает в той же CSS-системе координат.
5. **Плавность.** Сырые координаты указателя являются target state; текущая
   позиция догоняет их через `requestAnimationFrame` и easing. При `prefers-reduced-motion`
   переходы заменяются на мгновенные или укороченные.
6. **Hover/click.** Hover меняет только preview. Click меняет `selectedMovieId`,
   фиксирует выбор и обновляет панель деталей. Повторный клик/закрытие снимает
   фиксацию по согласованному UX-контракту.
7. **Изображения.** Poster URL берётся из текущего DTO приложения. Изображение
   кэшируется по URL/ID, ошибки дают безопасный placeholder, а загрузка не должна
   блокировать layout или отображение списка.
8. **Состояние.** Renderer владеет только геометрией, кадром и визуальным focus;
   page manager владеет фильтрами и выбранным фильмом. Не создавать второго
   владельца selection или layout mapping.

## 6. Порядок реализации

### Шаг 1. Зафиксировать входной snapshot

Проверить, что renderer получает только текущий отфильтрованный массив и что для
каждого фильма доступен стабильный ID, title и poster URL. Нормализовать числа и
необязательные поля в одном месте. Не сортировать исходный массив внутри Canvas.

**Готово, если:** один и тот же snapshot даёт одинаковый `layoutIndex`, а при
дубликате ID тест сообщает ошибку, а не рисует два неразличимых владельца.

### Шаг 2. Сделать детерминированную сетку

Рассчитать число колонок/строк по размеру viewport и количеству элементов.
Сохранить `baseX/baseY`, базовый размер и z-приоритет. При `setMovies()` сразу
инициализировать новые элементы в рассчитанных ячейках.

**Проверка:** при отключённых изображениях и при медленной загрузке ни один
placeholder или poster не появляется пачкой в левом верхнем углу.

### Шаг 3. Добавить локальную линзу курсора

Перевести pointer в координаты Canvas, вычислить расстояние до центров ячеек и
применить кусочно-заданное smoothstep falloff с контрольными точками: `0R = 4x`,
`.25R = 3.3x`, `.5R = 2.3x`, `R = 1.1x`, `1.25R = 1x`. Для всех ячеек также
применить монотонную radial/barrel transform позиций; базовая сетка не
перестраивается, а её screen coordinates получают согласованное искривление.

**Проверка:** центр, край и угол Canvas дают одинаково предсказуемую реакцию;
уход курсора возвращает все элементы к base scale; быстрый проход не оставляет
старую линзу в случайном месте.

### Шаг 4. Реализовать отрисовку и кэш изображений

Рисовать видимые/достаточно крупные постеры и placeholder для остальных.
Загружать сначала ближайшие к фокусу изображения, остальные — лениво.
`onload` и `onerror` должны инициировать безопасный следующий кадр, не меняя
порядок элементов.

**Проверка:** медленная сеть не ломает сетку, одна ошибка URL не останавливает
рендер остальных, повторный focus не создаёт бесконечные запросы.

### Шаг 5. Сделать hover и hit-test

Для каждого кадра получать screen geometry из base geometry и текущей transform.
Hit-test должен сначала применить `inverseTransform` через LUT к координате
указателя, найти исходную ячейку и проверить только локальных кандидатов с
учётом их деформированных screen bounds. Hover передавать в manager только как
ID фильма.

**Проверка:** наведение в центре выбирает фильм под курсором, а не первый фильм
массива; после resize hit-test совпадает с видимой картинкой.

### Шаг 6. Связать клик с информацией о фильме

По click выбрать film ID, закрепить состояние и обновить существующую HTML-панель
деталей. Не строить текстовые детали внутри Canvas. При новом фильтре очищать
выбор, если выбранный фильм больше не входит в snapshot.

**Проверка:** hover не фиксирует выбор; click открывает именно нажатый фильм;
панель не показывает данные предыдущего snapshot.

### Шаг 7. Довести responsive и accessibility

Обработать resize, DPR, клавиатурную навигацию и видимый accessible list fallback.
Canvas не должен быть единственным способом найти фильм: список и кнопки остаются
доступными для keyboard/screen reader. Проверить dark/light theme и reduced motion.
Точки фонового поля внутри активной области проходят ту же transform; внешний CSS
фон остаётся статичным как лёгкий hybrid layer.

### Шаг 8. Проверить производительность и визуальные границы

Снять кадры для 255 фильмов на desktop и узком viewport. Считать количество
активных image loads и убедиться, что pointer move не делает full DOM layout.
Если FPS на целевых устройствах устойчиво падает ниже примерно 55, сначала
уменьшить число одновременно декодируемых изображений и redraw area; WebGL не
вводить автоматически.

## 7. Критерии приёмки

- Режим «Сетка» не изменился и остаётся default.
- В режиме Canvas все фильмы имеют собственные стабильные ячейки.
- При первом кадре и во время загрузки нет stack в левом верхнем углу.
- Наведение в любой точке увеличивает локальную область под курсором, а не
  открывает карточку в фиксированном углу страницы.
- Увеличение и возврат происходят плавно и не меняют identity фильма.
- Hover показывает preview, click показывает details выбранного фильма.
- Фильтр, сортировка, очистка и повторная загрузка не оставляют stale selection.
- Resize и device-pixel-ratio не создают смещение pointer относительно постера.
- Клавиатура и fallback list позволяют выбрать тот же фильм без мыши.
- Ошибки poster URL не ломают остальные элементы.
- `npm run lint`, целевые тесты и `npm run build` завершаются успешно.

## 9. Риски и границы совместимости

- **Рост коллекции.** Canvas 2D подходит для текущих сотен элементов. При переходе
  к тысячам и выше отдельно спроектировать texture atlas/WebGL, сохранив контракт
  `movieId → cellIndex`.
- **Смена порядка.** Любая сортировка после назначения cell index может показать
  правильную картинку с чужими деталями. Поэтому reorder выполняется только через
  новый snapshot и полный пересчёт mapping.
- **DPR и CSS transform.** Нельзя использовать `canvas.width` как CSS-координату;
  все pointer bounds должны вычисляться через rect.
- **Сеть.** JSON-кэш и media-кэш — разные уровни. Метаданные не заменяют poster
  pixel source, а poster failure не должен блокировать selection.
- **Производительность.** Не загружать все крупные изображения только потому, что
  они находятся в массиве; вводить bounded cache и focus-priority loading.

## 10. Самопроверка решения

**Первый принцип:** пользователю нужно быстро исследовать коллекцию, не теряя
связь «постер → фильм». Это важнее визуального сходства с настоящей сферой.

**Слабое место:** Canvas 2D не повторит точную deformation physics референса.
Это приемлемо для зафиксированного scope; если нужна именно физика референса,
это будет отдельный WebGL-проект, а не небольшая правка текущей линзы.

**Проверка на ошибку:** если перенос части геометрии в `ratings.js` или повторное
позиционирование DOM-карточек снова появится, остановить реализацию и вернуть
единственного владельца mapping в `ratings-sphere.js`.

## 11. Итерация: кэш и непересекающаяся линза

По проверке реального поведения выяснилось две отдельные причины:

- `Image`-кэш жил только в памяти страницы, поэтому после reload создавался
  заново. Для poster bytes выбран `Cache Storage` с TTL 24 часа и ограничением
  350 записей; даты и LRU-метаданные хранятся отдельно в `chrome.storage.local`.
  Большую таблицу бинарных постеров в `chrome.storage.local` не складываем.
- Простое увеличение размера внутри фиксированной ячейки неизбежно создавало
  пересечения. Вместо перераспределения целых строк используется компактная
  радиальная линза: сетка сохраняет шаг, ближайшие постеры получают ограниченное
  смещение от курсора и масштабируются до 4x с запасом между соседями.
- Для фокуса добавлены кусочно-заданный radial falloff и затемнение периферии
  внутри прямоугольной поверхности без видимой круговой границы. Контрольные точки масштаба: `4x → 3.3x → 2.3x → 1.1x → 1x`
  на расстояниях `0R → .25R → .5R → R → 1.25R`. Только максимум 32 ближайшие
  ячейки допускаются к poster loading/drawing; группа рассчитывается по целевой
  позиции курсора, поэтому быстрый sweep не запускает декодирование всех
  промежуточных групп. Новые loads запускаются максимум по 4 за кадр, остальные
  элементы остаются силуэтами.
- Poster bytes сохраняются в extension-origin Cache Storage с версией схемы и
  TTL 24 часа; ключ нормализуется без query/hash. При miss renderer просит
  background fetch заполнить тот же кэш, а ушедшие из focus-группы loads отменяются.
- Пока режим видим и reduced motion не включён, Canvas продолжает мягкий
  детерминированный дрейф элементов; амплитуда меньше свободного зазора, поэтому
  визуальное «плавание» не ломает hit-test и не создаёт пересечений.

Старые рейтинговые данные не подменяются 24-часовым snapshot: metadata/ratings
остаются владельцем страницы, а persistent cache используется для повторного
получения poster bytes. Это экономит тяжёлую загрузку изображений, не показывая
устаревшие оценки и описания.

## 13. Retirement plan

Не удалять текущую grid view, DOM fallback или manager-level detail panel. Если
позже появится WebGL-режим для больших коллекций, он должен заменить только
renderer implementation, сохранив `movieId`, selection, фильтры, accessibility и
detail-panel contracts. Canvas 2D можно вывести из production только после
сравнительного FPS/visual/accessibility теста и отдельного согласования scope.

## 14. Итерация A: radial transform, LUT inverse и dev-настройки

- Параметры `k1`, `k2`, радиус и сила искажения доступны в dev-режиме через
  query-string или компактную dev-панель и применяются без пересборки расширения.
- `forwardTransform` работает для всех элементов snapshot, независимо от
  `MAX_FOCUS_POSTERS`; лимит 32 касается только загрузки/декодирования постеров.
- Радиальная таблица строится в нормализованном домене `0…1.25R`. На границе
  transform плавно соединяется с identity, поэтому `r2Max = 1.25R`.
- `inverseTransform` возвращает `0` для `r2 = 0`. При `r2 > r2Max` используется
  identity-fallback `r = r2`, а не clamp; входы не должны давать `NaN`.
- LUT inverse использует бинарный поиск и интерполяцию с одной уточняющей
  итерацией Ньютона; таблица перестраивается только при изменении параметров.
- Unit-тесты проверяют sampled monotonicity, положительную производную,
  round-trip accuracy, центр и значения за пределами таблицы.
