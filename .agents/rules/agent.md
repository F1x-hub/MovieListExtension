## Key Conventions
- **Catalogue routing**: Home category links use `catalog.html?category=films|series|cartoons|anime`; legacy `search.html?type=...` links redirect to the canonical catalogue route. Do not resolve KP IDs for an entire list page; resolve them only through the existing click-time MovieDetails flow.
- **Card ratings**: `MovieCard` keeps KP, IMDb, and TMDB ratings in separate fields; compact badges must label the provider and never display TMDB as KP.
- **Card rating enrichment**: Home (including featured cards) and Catalog enrich only visible cards in the background, use direct KP IDs immediately and deduplicate title/year identity searches for cards without IDs, prefer the hidden KP movie page for KP/IMDb ratings without opening visible tabs, use the legacy IMDb title-page parser only after a trusted IMDb ID is available, and cache KP/IMDb results in `movie_card_ratings_v4`; rating-required offscreen searches wait for hydrated KP result-card ratings before returning. The observer uses a 40px root margin, processes at most 6 cards per flush, does not use per-card detail-page fallbacks after transient timeouts, and exposes `[MovieRatingsTrace]`, `[KPCardTrace]`, and `[KPScraperTrace]` diagnostics. Initial rendering must not wait for this work; partial records render KP immediately and keep IMDb in a provider-specific skeleton/pending state.
- **Naming**: camelCase for javascript files (`FavoriteService.js`), kebab-case for styling/HTML/folders (`movie-details`), and uppercase prefix for UI variables.
- **Code Separation**: Logic should be written in dedicated services in `src/shared/services/` and cached via caching services (e.g., `RatingsCacheService.js`).
- **Bundled game data**: Static game dictionaries belong under `src/shared/data/` and are loaded through a dedicated in-memory data loader; do not persist immutable rank data in `chrome.storage.local`.
- **Rubik's Cube game**: Keep cube turns, solved-state checks, axis selection, and turn animation orchestration in `src/shared/games/RubiksCubeGame.js`; `GamesModal` only owns lifecycle, shared stats, overlay, and keyboard routing.
- **CSS**: Scoped class naming, CSS custom properties for theming (Light/Dark themes), and absolute responsive design layout.
- **Loading states**: Use the shared `app-loader` namespace from `common.css`; do not add new global `.spinner` or `.loading-spinner` variants.
- **Player styling**: Keep iframe/video geometry in `player.css`, not inline markup. Preserve the shared glass modal, theme variants, source buttons, and `PlayerSourceLifecycle` overlays.
- **Admin UI**: Keep the admin workspace visually aligned with catalogue pages: use shared theme tokens, compact section cards, and responsive data controls rather than a separate dashboard palette.
- **Card ratings**: List pages read cached ratings first; `MovieRatingsEnrichmentService` may use bounded KP/IMDb HTML parser fallbacks, while only `movie-details` invokes `RatingsRefreshService`.
- **Kinopoisk ID extraction**: Always use `Utils.extractKinopoiskId(item)` to resolve numeric Kinopoisk IDs from movies, DTOs, ratings, or Firestore bookmark documents. Never use raw `item.id` directly in link builders or API calls without validation, as Firestore documents often use composite keys like `${userId}_${movieId}` which cause HTTP 400 errors in `movie-details.html`.
- **MovieCard variants**: Use `variant: 'search'` for high-density 2:3 poster-dominant discovery grids without bloated descriptions or 3-column rating tables; default `variant: 'standard'` remains the full-detail community card.
- **Unrated movie cache**: Do not create or update Firestore movie documents for an unrated movie. Read and write its metadata and KP/IMDb data through `local_movie_cache_{kinopoiskId}` instead.
- **MovieDetails HTML Sanitization & Link Boundary**: Helper methods like `formatCrewCategory` are the sanitization boundary (internally escaping user names and query-encoding params); their output markup MUST NOT be wrapped in redundant `escapeHtml()` during template interpolation to prevent literal HTML string escaping.
- **MovieDetails Actors Grid**: Keep all actor cards in one `#actorsGrid`; collapsed visibility is three complete CSS-defined rows measured from `gridTemplateColumns`, while expanded casts stay fully visible across resize.
- This unified-grid rule supersedes older Phase 2B wording that referenced `.actors-grid--remaining` as a separate container.
- **Ratings Presentation Hierarchy**: The 250px left poster rail renders exactly 2 equal-width rating cards (Kinopoisk and IMDb, flex: 1 1 0). TMDB rating is preserved and surfaced cleanly inside the "О фильме" metadata grid (`.meta-item--tmdb`) with score and formatted votes count when `tmdbRating > 0`.
- **Seasons Visual UX, Continue Watching & Watched History (Phase 4A & 4C)**: Multi-season titles (> 1 season or 1 season + specials) render a horizontal scrollable pill selector (`.seasons-nav-pills`, `role="tablist"`). Single-season titles without specials omit the pill selector and display the season summary card directly. Season switching is pure DOM view toggling (0 network requests). Under Phase 4A & 4C, the subsystem maintains a strict two-layer architecture:
  1. *Layer 1 (Fast Volatile Resume)*: `ProgressService` (`viewing_progress_v1_{movieId}`) stores the single active `{ season, episode, timestamp, duration, completed }` updated every 15s. Drives the Continue Watching banner (`#seasonsContinueBanner`) and Generic Watch routing (`source: 'RESUME'`).

- **Profile Personal Dashboard**: `profile.html` keeps the existing profile summary as the stable entry point, then adds a responsive dashboard for the current user. - **User Account Approval Lifecycle**: Newly registered user profiles receive `approvalStatus: 'pending'`. Legacy users are migrated to `approvalStatus: 'approved'`. Profile updates must preserve `approvalStatus` unless specifically updated via admin tools.
- **Auth Gate**: Every auth entry point (email login, registration, Google login, session restoration in `initializeUI` and `authStateChanged`) queries the user's Firestore profile. Document creation in `users/{userId}` allows self-registration only with `approvalStatus: 'pending'` and `isAdmin: false`. User profile self-updates cannot modify `approvalStatus` or `isAdmin`. - **MovieDetails async lifecycle**: Every async MovieDetails operation that mutates page state or DOM after an `await` must capture and prove the active page-generation context before writing. Generation advances only for a different movie or unload; same-movie rerenders retain it so ready related-content data can rehydrate replacement DOM without a new provider request. `PlaybackController` is the sole progress persistence owner.
- **Reverse identity negatives**: `IdMappingService` reverse `kp:{mediaType}:{kinopoiskId}` not-found records must use `{ attemptedAt, retryAfter }` with a bounded TTL. Treat legacy negatives without `retryAfter` as stale and self-heal on access; metadata negatives also carry `metadataRecoveryVersion` so one retry is allowed after a recovery-algorithm update (current version 4). `forceRefresh` must bypass them but reverse authority remains restricted to trusted verified mappings.
- **MovieDetails dialogs**: True MovieDetails dialogs use `role="dialog"`, `aria-modal="true"`, an accessible name, one shared focus-entry/trap/restore lifecycle, and topmost-first Escape handling. The episode picker remains a non-modal popover.
- **MovieDetails performance tracing**: `window.MovieDetailsPerf` provides low-overhead marks, request counters, and bounded sanitized traces. Debug summaries require `localStorage.movie_details_perf_debug === '1'`; retain no more than 20 traces under `movie_details_perf_traces_v1`.
- **MovieDetails trace semantics**: Startup completion is a persisted snapshot, not a request cutoff. Late request settlement updates the same trace; parser diagnostics distinguish call, physical-network, cache-hit, and in-flight-dedup counts, and player preload separates dispatched from settled timing.
- **Seasonvar preload discovery**: `SeasonvarParser` owns bounded normalized-URL caches and in-flight maps for parsed pages, series info, and seasons. Public preload paths must use `cachedSearch()` and these helpers so overlapping work produces one physical page/playlist request without changing selection or playback behavior.
- **MovieDetails critical path**: Base metadata renders with neutral personal controls before profile, collections, rating, bookmark, or optional frames settle. Post-render personal reads run in parallel via `Promise.allSettled` and patch only owned UI regions under the active page-generation guard.
- **MovieDetails speculative cache**: Before auth resolves, only local/public cached movie metadata may render. Never start KP/TMDB aggregation, player preload, personal reads, or admin controls pre-auth; pass the single cache result into authenticated aggregation to avoid a duplicate cache read.
